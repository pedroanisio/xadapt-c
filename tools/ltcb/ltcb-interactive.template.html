LTCB Frontier Explorer

Every program on Matt Mahoney's Large Text Compression Benchmark, on enwik9 (10⁹ bytes of Wikipedia) and enwik8 (its first 10⁸), with this repository's cadapt drawn beside them. Lower bits per byte is better; times are the benchmark's nanoseconds per byte on assorted machines.

Phases of the frontier

A phase is a run of frontier points held by one family; shaded bands alternate per phase and a band runs until the next family's first point. Rules mark each change with what it buys. The strip below is the marginal gain of each step, bits per byte per tenfold time: spikes are cliffs, troughs plateaus. Size removed per second

For enwik9 the ns-per-byte figure is numerically the run time in seconds, so this is (10⁹ − output) ÷ time: how fast each program makes data smaller.

enwik8 → enwik9 scaling

Fitted power law across the published pairs, with cadapt's predicted enwik9 (and its interval) drawn from its enwik8 result; a measured enwik9 is drawn as the solid diamond.

Weighted efficiency

Cost = bpb × (compress + decompress ns/B)α × (memory MB)β, lower is better. α and β say how much a tenfold increase in time or memory is worth in ratio terms; at α = β = 0 this is the plain ranking. Units cancel in the ranking. The table on the right is the winner for each weighting.
