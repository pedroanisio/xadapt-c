# cadapt 0.12.0

Part of [adapt](../../README.md). The release notes: what this release is,
how to install it, what it reads and writes, how it measures, and how to
upgrade from 0.11.0. The complete list of changes is the `[0.12.0]` entry
of [CHANGELOG.md](../../CHANGELOG.md).

## Highlights

- **A new model.** Four first-layer arbiters (two of them keyed per file by
  the byte classes, the markup nesting or recall), a second estimation
  stage, a context table of up to 2^26 blocks, ten more contexts in the
  max profile, run memories, a second max model with int16 arbiters, and
  a text transform whose book both sides build as they code. Container
  versions 19 to 85; 0.11.0 wrote 13 to 15 (see *Upgrading*).
- **Four profiles.** `--fast`, the default, the new `--mid` (seven fixed
  contexts, one arbiter) and `--max`; a memory tier `-0` … `-11` that is
  encode's only memory setting and the memory every decoder of the file
  needs.
- **Folders, with fidelity.** A folder is one container: modes, times,
  ACLs, extended attributes, symbolic and hard links and sparse files come
  back (archive versions 1 to 4).
- **Threads, proof, budgets.** `--threads` cuts segments and codes them at
  once to the same bytes as one thread; `--verify` proves the container
  as it is written; `decode --max-memory` and `--max-output` refuse a
  container before allocating, naming the numbers.
- **The interface, stated.** `adapt.h` opens with its contract —
  ownership, lifetimes, threads, errors, limits — and four examples in
  `adpat/c/examples/` hold it; `SUPPORT.md` states what a release
  promises the next.
- **Release engineering.** `make install`, `make release` with checksums,
  an SBOM, a build manifest and a NOTICE; the gates as two workflows;
  an audit under analyzers, sanitizers and three fuzz harnesses.

## Installing

From the release tarball for your platform (the checksums are in
`SHA256SUMS`, signed by nothing — compare them with the release page):

```sh
sha256sum -c SHA256SUMS --ignore-missing     # macOS: shasum -a 256 -c SHA256SUMS --ignore-missing
tar -xzf cadapt-0.12.0-linux-x86_64.tar.gz
sudo cp -r cadapt-0.12.0-linux-x86_64/{bin,lib,include,share} /usr/local/
cadapt --version          # cadapt 0.12.0 (format versions 19 to 85)
man cadapt
```

The layout is the one `make install` writes, relocatable under any
prefix: `bin/cadapt`, `lib/libadapt.a`, `include/adapt.h`,
`share/man/man1/cadapt.1`, with `LICENSE`, `NOTICE`, `CHANGELOG.md`,
`sbom.spdx.json` and `build-manifest.json` beside them.

From source (a C99 compiler and `make`; nothing else):

```sh
tar -xzf cadapt-0.12.0-src.tar.gz && cd cadapt-0.12.0
make                                  # adpat/c/build/cadapt, libadapt.a
make install PREFIX=/usr/local        # DESTDIR=… for a staging root
```

Linux and macOS with GCC or Clang are supported; Windows compiles under
MinGW and is not validated ([SUPPORT.md](../../SUPPORT.md)). This is the
first release whose suites ran on macOS in CI: two macOS-only defects
they found are fixed in it (a symbolic link's mode was checked but never
applied on restore, and a timestamp before 1970 refused the file — see
the changelog's Fixed entries).

## Using it

```sh
cadapt encode report.pdf                    # report.pdf.adpt, the normal profile, tier -9
cadapt encode photos/ -o photos.adpt        # a folder as one container
cadapt encode big.log --max -6 --verify     # the max profile at the 94 MiB tier, proven
cadapt encode huge.csv --threads 4          # segments on four threads, the same bytes as one
cadapt decode report.pdf.adpt               # report.pdf
cadapt decode photos.adpt -o photos-copy    # the folder restored, links and holes included
cadapt info big.log.adpt                    # the model, what decoding needs, the sizes
tar c src | cadapt encode - --fast > src.tar.adpt
cadapt decode - < src.tar.adpt | tar x
```

The library: link `libadapt.a` with `-pthread` and include `adapt.h`;
[adpat/c/examples/](../../adpat/c/examples/) shows a round trip in
memory, streams through callbacks, a folder through the archive writers
and unpacker, and the contract.

## Compatibility

- **Reads:** every container version 19 to 85, and archive versions 1 to
  4 — forever, as [SUPPORT.md](../../SUPPORT.md) promises; the decoder
  suite decodes a pinned file of each.
- **Does not read:** versions 13 to 15, what 0.11.0 wrote, nor 10 to 12
  (the Rust crate's). This was decided when the model of version 19
  landed (LOCKS.md, 2026-09-14) and is the one exception to the promise
  above, made before the promise was stated; nothing written from version
  19 on will ever be refused.
- **Writes:** 84/85 for the normal profile (19/22 when the classic keys
  win a file), 20/23 fast, 76–79 mid, 72–83 max, 25–52 for the
  experimental predictors and the BMP transform. A 0.12.0 file needs
  0.12.0 or later to decode.
- **Command line:** `--version` prints `cadapt 0.12.0 (format versions 19
  to 85)`; take the release from the second word. `--mid`, `--explain`,
  `--transform`, `--allocation`, `--contexts`, `--adaptive` and the tiers
  `-0` … `-11` are new since 0.11.0; `encode --max-memory` is gone — the
  tier is encode's only memory setting; `decode --max-memory` stays.
- **The C interface:** `adapt_stats` grew (`class_code` … `trial_bytes`)
  and `adapt_sizes` gained the fields the new versions need; a program
  compiled against 0.11.0's header is rebuilt. The functions 0.11.0
  declared keep their names and meanings; new ones were added.

## Upgrading from 0.11.0

0.12.0 refuses the containers 0.11.0 wrote (versions 13 to 15). Before
replacing the binary, decode what you keep in that format with 0.11.0,
or keep 0.11.0 installed beside it (`make install PREFIX=/opt/cadapt-0.11.0`
from the `v0.11.0` tag) — `cadapt info` names a file's version. Installing
0.12.0 over 0.11.0 replaces `cadapt`, `libadapt.a`, `adapt.h` and
`cadapt.1` in place; nothing else of 0.11.0's is on disk. Files written by
0.12.0 decode with every later release.
