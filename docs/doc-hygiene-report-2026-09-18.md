**What**: a test that the first `## [x.y.z] — date` heading of
`CHANGELOG.md` names `CADAPT_VERSION` from `adpat/c/cadapt.c`, and that when

**How**: one method in `tools/test_docs.py` (`ChangelogTest`), reading the

**What it replaces**: the by-hand check performed for this release.

**Drift risk if not automated**: `tools/release.sh` already refuses a tag
that does not match `CADAPT_VERSION`, but nothing refuses a changelog that
does not.

#### 2: Every cited `make` target exists where it is cited

**What**: for every `` `make [ -C adpat/c] [VAR=…] target` `` in a tracked
Markdown file or the man page, the target is a rule of the Makefile that
invocation reaches (root rules are `all test clean install uninstall`,
`check`, `gate`, `ratio-floor`, `corpus`, `corpus-floor`, `memory-gate`,
`release`, `test-install`, `sbom`, `manifest`, `reproduce`, `ltcb`,
`ltcb-release`, `bench plot`; the codec's include `sanitize`, `coverage`,
`check-long`, `fuzz*`).

**How**: the regex `make(?: -C adpat/c)?(?: [A-Z_]+=\S+)* ([a-z][a-z-]*)`
over each file, against `^([a-z][a-z -]*):` in each Makefile (a rule line
may name several targets). Or, cheaper, forward `sanitize coverage
check-long` from the root Makefile and the four citations become true.

**What it replaces**: nothing — this was never checked.

**Drift risk**: the first command in `SECURITY.md`'s verification paragraph
fails today.

an allow-list for run outputs and install layouts. The pass that found the
findings above took ten lines.

**Drift risk**: five documents named `bench/…` tooling after it moved to
`tools/`; only the later locks were updated.
